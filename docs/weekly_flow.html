Vietnam Weekly 制作フロー & GitHub Actions 連携ガイド

週次レポート「Vietnam Weekly」がどう作られているか、GitHub Actions が何を自動化しているか、そしてベトナム個別株・中国情報をどの工程に差し込むかを、連携のために1枚に整理したもの。

対象読者 投資調査部／連携メンバー 媒体 Vietnam Weekly（月曜発刊・先週5営業日） 版 v1・2026-08-10 区分 投資調査部 制作フロー・リファレンス
要約

3行でいうと

1 ・ 素材は自動で貯まる
GitHub Actions が毎営業日、確定市況と現地ニュースを自動取得して outputs/ に蓄積。月曜に一括取得しない。
2 ・ 発刊は半自動
月曜朝、貯まった素材から 人（投資調査部＋Claude） が集計・執筆・組版・再鑑して発刊。全自動にはしない。
3 ・ 連携は差し込み式
個別株はベトナム個別株 担当、中国情報は中国情報 担当へ。決まった工程・締切・受け渡し形式で本文に差し込む。
01

そもそも何を作っているか

日経ヴェリタス相当の週次マガジン。無料データ（VNDirect）＋毎日の蓄積＋リサーチ集で組む。芯は「数字で構造を暴く」——「上がった」で終わらせず、誰が・何が・どれだけ指数を動かしたかを一枚めくって見せる。

  • 表紙メイン記事型。背骨は VN30 を1社ずつ深掘りする連載「企業クエスト」。
  • 物差しは常に VN-Index（読者が知っている市場全体）。VN30・上位10社を主語にしない。
  • 読者は CAM 運用チーム＋マーケ教材。誌面に個人名は出さない。
  • 社内・グループ内限定。試作品免責・顧客配布厳禁を毎号掲載。配信は投資調査部の手（自動送信しない）。

公開ポータル: yumiba924-a11y.github.io/shishimaru-vn-news（GitHub Pages・main /docs）。リポジトリ yumiba924-a11y/shishimaru-vn-news。

02

GitHub Actions の仕組みと役割

ワークフローは .github/workflows/ に2本。要点は「日次 Action ＝ 週次のための素材工場」。市況もニュースも月曜にまとめて取りにいくと、時間がかかり・間違いが出て・粒度も落ちる。だから毎営業日、確定した分だけ漏れなく吸い上げておく。

daily.yml ― 素材工場（毎営業日・稼働中）

2つの cron で1日2便。GitHub の cron は UTC 指定なので、日本時間との対応を明記しておく。

夕方便 18:00 JST = cron 0 9 * * 1-5 朝便 07:00 JST = cron 0 22 * * 0-4 手動 workflow_dispatch
各営業日 ubuntu-latest / pwsh
Step 1
fetch_vn30.ps1
VN30・指数・外国人フロー（net_val / room）を取得
→
Step 2
interpret.ps1
寄与度（weight×%）・HOSE breadth を算出 → interpreted.json
→
Step 3
collect_news.ps1
現地4紙を無料翻訳 → news_raw（週次の素材）
→
Commit
outputs/ に蓄積
github-actions[bot] が日付別に push。変更なしならコミットしない
押さえどころ 朝便はニュースの網羅性のため、夕方便は確定市況の主軸。outputs/ だけを add し、公開誌面（docs/）には一切触らない。だから月曜の制作は「良質な素材から組むだけ」になる。

weekly.yml ― 旧ししまる自動生成（cron 停止中）

旧「ししまるVN30分解新聞」の月曜自動生成。現在は cron を止め、手動実行（workflow_dispatch）だけ残置。現行の Vietnam Weekly は自動生成せず、人が組む。復刊する場合はここに schedule を戻す。

ワークフロートリガーやること成果物状態
daily.yml cron 2便（18:00 / 07:00 JST）＋手動 fetch → interpret → collect_news outputs/ に市況・ニュース蓄積 稼働中
weekly.yml 手動のみ（cron 停止） weekly.ps1 で集計＋Chrome でPNG化 旧ししまる新聞 HTML/PNG 停止・残置
連携メンバーが Actions を触るとき 普段は自動なので操作不要。手で回したいときは GitHub の Actions タブ → daily-collect-for-weekly → Run workflow（workflow_dispatch）。デプロイの成否は gh run list -L 1 で確認。Pages デプロイは時々落ちるが gh run rerun <id> --failed でほぼ復旧する。
03

週次作成フロー（月曜朝）

発刊日＝今週月曜、対象データ＝先週の営業日（月〜金）。自動で貯まった素材を土台に、人が9ステップで仕上げる。担当の色分けは 自動＝GitHub Actions、 Claude＝集計・執筆・組版、 投資調査部＝判断・配信。

  1. 0
    素材の自動蓄積 自動
    前週の各営業日、daily.yml が市況・寄与度・ニュースを outputs/ に蓄積済み。ここまでは人が動かない。
  2. 1
    データ確定 Claude
    週次TR（調整後 adClose）・寄与度（恒等式で検算）・セクター騰落・外国人フロー・分解チャートを確定。自前APIの実測が原則。
  3. 2
    本文執筆 Claude 投資調査部
    企業クエスト → 概況リード → ニュース4枚 → 注目材料。リサーチ集の docx から選抜し、数値は自前APIで裏取り。
  4. 3
    組版 Claude
    原器 docs/weekly01.html を複製し、数字・本文・写真・号表記を差し替え。表紙写真は投資調査部が weekly_covers/ に用意。
  5. 4
    検版 Claude
    Edge headless でフルページPNG化 → 全セクションを目視。折り返し・バーの向き・写真出典を確認。
  6. 5
    セルフ再鑑（必須ゲート） Claude 投資調査部
    数字の1対1照合・単位の桁・実在人物と時事日程のWeb確認・VN-Index比への着地など10項目。「外部の再鑑者が突く前に自分で監査する」。
  7. 6
    サイト更新 Claude
    docs/data/site.js に追記するだけでポータル・攻略マップ・財閥図鑑・決算通信簿が同時更新（データ駆動）。
  8. 7
    push → デプロイ監視 Claude 自動
    対象ファイルを明示 add → commit → push。GitHub Pages が自動デプロイ。gh run list で成否確認、落ちたら rerun。
  9. 8
    発刊・メール文 投資調査部
    配信用メール（件名＝【CQC投資調査部】Vietnam Weekly VOL.NN 発刊のお知らせ）を用意。送信は投資調査部の手。転送厳禁の注意と次号予告を添える。

05

運用メモ・注意

  • ローカル専用フォルダ: ネタ/・weekly_covers/・写真/・チャート/・docx類は公開リポジトリに入れない。git add -A 禁止、対象ファイルを明示して add。
  • 全角パス: リポジトリ名は半角 VN30新聞。見つからない時は glob で解決。
  • 時点表現: 「本日・今日・明日・昨日」は使わない（閲覧タイミングでずれる）。絶対日付か「今週・来週」で。
  • 免責: 全ページ共通フッターに「社内・グループ内限定／試作品／投資勧誘ではない／配布厳禁」。削らない。
